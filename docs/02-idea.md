# 02 核心 idea

[返回首页](../README.md) · [上一章：问题与任务](01-problem.md) · [下一章：具体方法](03-method.md)

## 2.1 用简化孪生预测一次观察有没有用

从住宅导览视频估计布局，再用现成三维模型拼出一个近似的家庭场景。它保留任务需要的距离、遮挡和通行关系，未拍到的地方标为未知。

机器人用这个场景回答两个相连的问题：出发前，站在哪里比较容易得到可靠答案；到达后，眼前的画面更支持哪种家庭状态。

## 2.2 出发前：比较观察位置

假设要确认纸箱还在不在，机器人在模型里试几个位置和朝向，预测从各处能看见目标区域的多少、距离有多远，再结合判断模型的离线表现，估计能否给出明确且正确的答案。

模型里的柜门可能宽了一点，家具位置可能偏了一点。系统根据实测误差生成多个可能版本，优先选择在较不利的版本中仍然有用、又便于到达的位置。

## 2.3 到达后：用两种参照解释实拍

机器人在当前相机位置生成两组参照：目标在原位，目标不在原位。判断模型结合实拍、目标照片和参照，在“在、空、挡住、看不清”四个选项上给出概率。

参照使用深度和掩码，描述距离与轮廓。目标真实外观由照片提供，因为检索到的替代模型可能与实物长得不同。

## 2.4 只检查会影响当前任务的信息

如果“纸箱在”和“纸箱不在”会得到同一条路线，就不必为这个任务额外确认纸箱。若两种状态会改变路线、任务动作或回答，就把它交给取证模块。

取证模块比较三种做法：去观察、问主人、直接执行。代码负责路程、几何和代价计算，模型负责需要语义或视觉理解的小判断。

## 2.5 哪些内容准备作为论文主线

| 内容 | 当前定位 | 需要的证据 |
| --- | --- | --- |
| 同一孪生同时支持选站位和到站判断 | 核心机制 | 两个环节的作用及组合效果 |
| 考虑建模误差的站位选择 | 核心机制的一部分 | 误差变化时，观察结果是否更可靠 |
| 孪生参照的四类视觉判断 | 核心机制的一部分 | 是否减少“挡住”和“空”的混淆 |
| 视频建模、资产检索、局部修正 | 支撑组件 | 成本、误差和可运行性 |
| 任务分流、物体绑定要求、完成检查 | 系统与任务设定 | 是否能稳定支持不同家庭任务 |

当前最需要先验证两件事：家里是否常有“原位置看不清，换个位置就能看清”的情况；参照渲染是否确实帮助判断模型。与既有工作的重合程度见 [05 相关工作](05-related-work.md)，实验见 [06 验证计划](06-evaluation-plan.md)。
