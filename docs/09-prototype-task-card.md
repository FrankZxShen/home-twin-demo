# 09 原型任务卡

[返回首页](../README.md) · [上一章：决策记录](08-decisions.md) · [下一章：核验记录](10-validation.md)

依据 2026-11-04 的本地任务卡整理。下面的实施范围和资源配置仍是提议；本轮仅准备讨论材料，尚未下载模型或启动实验。

## 9.1 本轮研究问题

不训练导航策略，先检验 H1、H3、H4：是否值得换站位，可能场景是否覆盖实际遮挡，以及多种补全是否比单一地图更会选位置。随后用离线实验 B 检查四类判断 H5。

## 9.2 输入与输出

| 类型 | 内容 |
| --- | --- |
| 输入场景 | ProcTHOR 住宅、目标与遮挡物配置、脚本导览路线；故意漏拍部分区域 |
| 输入任务 | 待验证命题 z、信念 b(z)、当前位姿、额外路程预算 |
| O1 | 从 RGB 导览视频恢复的语义地图、未知区域和建图误差报告 |
| O2 | 默认 K = 20 个可能场景；每物体默认前 5 名资产候选；观测一致性检查 |
| O3 | 共同候选站位、几何可见度评分、单一地图及补全方法的选位结果；完成 B 后增加 ρ 与 Q20 评分 |
| O4 | VLM、文字／JSON 选项模型、规则、检测器四种判断实现，以及校准与混淆统计 |
| O5 | 信念更新及需要再观察时的下一站位 |
| O6 | A、B 的结果表、可靠性曲线、耗时和失败案例 |

## 9.3 最小示例

导览视频只拍到储物柜正面，侧面进深未知；目标纸箱可能在柜门后，也可能已移走。生成不同进深的补全，在相同可到达候选中比较观察位置，再获得实际 RGB-D 并更新 b(z)。

“近侧面可能仍被挡，远侧面可能看清”是待构造的机制例子，不是测得结果。先确认几何确实满足这种关系，再运行算法；不能预先要求方法一定选出更优结果。目标在和不在的两种配置均需运行。

## 9.4 拟交付内容

| 模块 | 交付与检查 |
| --- | --- |
| 建图 | 单住宅导览视频到语义地图的一条命令；类别、位置、朝向、尺寸、mAP25、漏检和误检报告 |
| 补全 | K 场景、候选资产清单、与观测的一致性误差；跨资产库重复检查，不能只看不同命名空间的 ID |
| 渲染 | 独立渲染器的深度／掩码；真值布局导出只用于同位姿渲染诊断，误差容差待定 |
| 选站位 | 相同候选、地图和预算下的 B9 与各补全比较；记录评分、路程、选位与实际看清结果 |
| 判断 | 四类输出、温度缩放或保序回归、混淆模型和响应时间 |
| 更新 | 不重复计入同站位相邻帧；遮挡／看不清不被当成目标存在或消失 |
| 实验 | A 的可见度、覆盖宽度、站位效果和建图统计；B 的分类、校准、条件及消融结果 |
| 复现 | README、配置、种子、数据划分、版本和逐步日志；新环境复现最小示例 |

A 计划从 30 个关键位置开始；判断现象普遍性需另有未筛选样本。B 计划使用 30 套住宅，20 套开发、10 套最终测试，开发池内划分待定。

B 的条件包含无噪声深度、加噪声深度、RGB-only、相似物体替换，消融目标照片与渲染参照。RGB-only 下不得继续使用模拟器深度作为输入；缺失模态的处理必须显式记录。

## 9.5 原型范围与后续阶段

第一轮聚焦建图、补全、选站位、J3 判断和信念更新。用 Teleport 到达候选位置时，只能检验观察结果；到站路线可行性与预算仍需规划检查。这类结果不能直接作为真实导航成功率。

G1 完整解析、G6 在线导航、G7 完成判断、四天任务序列、询问主人、跨房间身份恢复，以及 Isaac Sim、UE5 和真机留在后续阶段。

## 9.6 开始实现前需要确定

- 代码位置、运行机器、GPU 与显存、Python/CUDA 环境、AI2-THOR 部署方式。
- VLM 或 API、Jev 可用接口、数据与权重下载量、存储和推理预算。
- 室内结构提取、尺度对齐、资产裁剪与扰动约束。
- AI2-THOR 动作与对象配置接口、资产格式和尺度。
- 标签优先级、软概率似然、开发／校准／测试划分、渲染与观测一致性的容差。
- A、B 的实际收益标准，在最终测试前固定。

若初期借用真值墙体，必须标为“墙体布局已知”的诊断条件。原型跑通与科研假设得到支持分别记录：算法可运行但没有收益，也是有效实验结果。
