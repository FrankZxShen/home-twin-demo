# 03 具体方法

[返回首页](../README.md) · [上一章：核心 idea](02-idea.md) · [下一章：工具与实现](04-tools.md)

本章按[框架图](../figures/home-twin-framework.png)的 (a)、(b)、(c) 三个分区说明方法。

## 3.1 输入与输出

输入包括住宅导览 RGB 视频、三维资产库、主人指令、已有家庭记忆，以及运行时的 RGB-D 和机器人位姿。RGB-D 指彩色图像和对应的深度图。

输出包括下一步动作、家庭状态的概率判断、更新后的物体记忆与要求状态，以及有观测依据的任务回复。

## 3.2 图 (a)：从视频建简化家庭模型

1. 从导览视频估计深度、相机内参和位姿。
2. 检测并分割物体，跨帧融合成带朝向的三维框，保存类别、位置、尺寸和外观截图。
3. 提取墙、门、地面等室内结构。具体方法待选择。
4. 按类别、几何尺寸和外观从资产库检索，保留前五名。
5. 用排名第一的模型拼装名义孪生，生成可通行区域。没有观测到的地方保留未知标记。
6. 机器人经过任务附近时，用实测深度与模型配准，修正附近家具和遮挡部件的位置。

执行环境与检索资产库分开：原型中执行环境使用 ProcTHOR 资产，孪生从 Objaverse 等资产库检索。直接读取模拟器真实布局的孪生仅用于上限对照。

需要区分两种校准：**建模误差测量**回答模型可能偏在哪里；**判断模型校准**回答模型的概率和实际正确频率是否一致。两者分别进入图 (b) 的扰动生成和可靠性查表。

## 3.3 图 (b)：选出需要验证的信息

把任务依赖的信息写成可判断真假的命题，例如“纸箱仍在走廊原位置”。机器人记录命题为真的概率。

系统分别按命题为真和为假生成计划。如果动作或回答会变化，就继续取证；如果不变化，就继续当前任务。

## 3.4 图 (b)：考虑模型误差，选择观察位置

在可通行区域采样位置和朝向，也保留原路线上的位置。候选点必须满足观察路程预算，且不违反当前生效的要求。

根据离线实测误差生成多个孪生版本，覆盖家具位置、朝向、尺寸和定位偏差；从前五名检索结果中替换未校准的遮挡部件；按实测概率模拟漏检和误检。

每个版本都预测目标区域的露出比例和观察距离，再查判断模型的离线标定表，得到“明确判断目标在或不在，并且判断正确”的概率。

当前方案的站位评分为：

```text
站位得分 = 多个孪生中正确分辨概率的第 20 百分位数
           − β × 到这个站位要多走的路
```

这里取偏低的分位数，是为了考虑模型偏差带来的不利情况。β 用于权衡判断机会与路程。原型默认生成 20 个扰动版本，这些数值属于待验证配置。

选出观察位置后，继续比较去看、问主人和直接执行的期望代价。代价包含额外路程、违反要求、无谓绕行和主人时间。最终报告时仍分别列出两类错误。

## 3.5 图 (c)：用同位姿参照判断现场

到达后，判断模型接收四类输入：

| 输入 | 提供的信息 |
| --- | --- |
| 当前 RGB-D 和位姿 | 现场外观、距离和观察位置 |
| 目标在／不在的两组深度及目标掩码 | 两种假设在当前视角下的几何参照 |
| 目标的真实照片 | 应该辨认哪个物体 |
| 根据实测深度得到的遮挡掩码 | 哪些区域被更近的表面挡住 |

两组参照采用相同相机位置和背景几何，仅改变目标是否存在。

| 输出 | 定义 | 后续处理 |
| --- | --- | --- |
| 在（Present） | 能看到目标全部或一部分 | 支持目标在场 |
| 空（Empty） | 目标区域看清了，目标不在 | 支持目标不在 |
| 挡住（Occluded） | 区域被遮挡，无法判断目标在不在 | 保留不确定性，考虑换站位 |
| 看不清（Unclear） | 过远、过暗或模糊，无法判断 | 保留不确定性，考虑靠近或换站位 |

四项输出概率在留出的住宅上校准。代码通过离线估计的混淆模型获得观测似然，再用贝叶斯更新结合旧信念。模型输出的“在”概率与记忆中的在场概率是不同量，不能直接相互替换。

“挡住”和“看不清”应提供很弱的存在性证据。同一站位连续几帧按一轮证据处理，避免重复计数。具体软概率如何进入混淆模型，需要在实现时固定，见 [07 待讨论问题](07-open-questions.md)。

## 3.6 更新记忆与长期要求

| 状态 | 含义 |
| --- | --- |
| 生效 | 当前有足够证据支持在该物体附近执行要求 |
| 待确认 | 现场证据不足，需要重新判断 |
| 暂停 | 已有足够证据表明物体离开原位置，原位置恢复通行 |
| 撤销 | 主人明确取消了这条要求 |

长期要求绑定具体物体。在别处认出同一个物体后，恢复要求并更新执行位置。物体身份不确定时，靠近观察或询问主人。

新的几何观测也写回孪生。仍未确认且有预算时，系统重新选择观察位置；完成条件有证据支持时，回复主人；预算用完时，报告已检查范围和未解决的信息。

## 3.7 完整系统中的模块位置

| 模块 | 负责什么 | 与框架图的关系 |
| --- | --- | --- |
| G1 解析与分流 | 识别任务、长期要求和外部工具问题 | 图 (b) 的任务输入之前 |
| G2 家庭记忆与孪生 | 保存模型、物体信念和要求 | 图 (a) 及图底部反馈 |
| G3 任务规划 | 找到会改变动作或回答的命题 | 图 (b) 上方 |
| G4 取证决策 | 选站位，比较看、问、直接执行 | 图 (b) 主体 |
| G5 观测更新 | 四类判断、身份判断、更新记忆 | 图 (c) 主体 |
| G6 执行器 | 导航、拍照、询问、调用工具 | 图 (b) 的动作分支 |
| G7 完成检查 | 检查证据是否满足完成条件并回复 | 任务执行之后 |

图中重点展开 G2、G4、G5。其余模块作为系统接口保留。
